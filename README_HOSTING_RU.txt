STICK ARENA 2.4.2 — УСТАНОВКА НА VPS В РОССИИ

Рекомендуемый вариант для игры с друзьями — один постоянно работающий VPS в российском дата-центре. На нём одновременно запускаются сайт игры и Node.js-сервер матча. Игроки открывают один HTTPS-адрес, а WebSocket подключается к тому же домену.

ВАЖНО О ВЫБОРЕ ХОСТИНГА

- Выбирай обычный VPS/VDS с постоянной работой, а не бесплатный сервис, который засыпает.
- Для первого запуска разумно начать с 2 vCPU и 2 GB RAM. Это отправная конфигурация, а не гарантия FPS или задержки; фактическая нагрузка зависит от режима, числа врагов и количества одновременных комнат.
- Если все игроки находятся в России, начни с дата-центра в Москве или другом городе, который даёт лучший маршрут именно вашим провайдерам. Если часть игроков находится далеко, размещение в России не обязательно уменьшит задержку для всех.
- Нужны публичный IPv4-адрес, возможность открыть входящие TCP-порты 80 и 443, домен и поддержка Docker. Для автоматического HTTPS Caddy должен иметь доступ к домену и этим портам.
- Название провайдера само по себе не гарантирует доступность в России или низкий ping. Перед оплатой проверь, что личный кабинет, оплата и сеть доступны из региона каждого игрока.

ЧТО УЖЕ ПОДГОТОВЛЕНО В ПРОЕКТЕ

- Dockerfile запускает Node.js-игру на порту 8080.
- docker-compose.yml запускает игровой сервер и Caddy.
- Caddyfile проксирует HTTP и WebSocket через HTTPS/WSS.
- Сервер имеет проверку состояния по адресу /health.
- Caddy автоматически получает и обновляет TLS-сертификат, когда домен направлен на VPS и порты 80/443 доступны.

УСТАНОВКА

1. Закажи VPS с Ubuntu LTS, публичным IPv4 и указанными выше ресурсами.
2. Привяжи домен к серверу: создай A-запись для поддомена игры (например, game.example.ru) со значением IPv4-адреса VPS. Подожди обновления DNS.
3. Подключись к VPS по SSH.
4. Установи Docker Engine и Docker Compose Plugin по официальной инструкции для своей версии Ubuntu. Нужны команды docker и docker compose.
5. Загрузи весь проект в одну папку на VPS. В корне должны лежать index.html, server.js, game-engine.js, package.json, Dockerfile, docker-compose.yml и Caddyfile, а также папки js и css.
6. В этой папке создай файл .env на основе .env.example и впиши свой домен:

   DOMAIN=game.example.ru

7. Убедись, что сетевой экран VPS разрешает входящие TCP 80 и 443. UDP 443 можно оставить открытым для HTTP/3; для обычной игры он не обязателен.
8. Запусти проект:

   docker compose up -d --build

9. Посмотри состояние:

   docker compose ps
   docker compose logs -f game proxy

10. Когда Caddy получит сертификат, открой https://game.example.ru. В меню «Онлайн» адрес сервера подставится автоматически.
11. Открой тот же адрес на телефоне друга. Один игрок создаёт комнату, второй вводит код.

ОБНОВЛЕНИЕ ИГРЫ

Загрузи новые файлы в ту же папку на VPS и выполни:

   docker compose up -d --build

После перезапуска процесса текущие комнаты завершатся: комнаты и матчи хранятся в оперативной памяти, база данных для их сохранения не используется.

ПРОВЕРКА СОЕДИНЕНИЯ

В меню «Онлайн» нажми «Проверить задержку». Игра отправит серверу WebSocket ping и измерит время до pong. Это RTT до сервера в текущей сети. Результат не гарантирует такую же задержку в каждом матче: маршрут может меняться, а нагрузка сервера и устройства влияет на игру.

О ЧЁМ НУЖНО ПОМНИТЬ

- Смена игрока, который создаёт комнату, не переносит физику на его устройство. Матч рассчитывает VPS.
- VPS в России обычно логичнее для игроков с российскими провайдерами, но маршрут зависит от конкретного интернет-провайдера. Нулевую задержку гарантировать нельзя.
- Не запускай две копии сервера на одном домене и не используй одновременно старый URL Render и новый VPS URL. Все игроки комнаты должны подключаться к одному серверу.
- Не закрывай SSH-сессию с остановкой контейнера. Docker настроен на автоматический перезапуск после выхода процесса или перезагрузки VPS.
- Если игровой сервер упал, проверь docker compose logs -f game. Если сайт открывается, но онлайн не подключается, проверь Caddy и входящие порты 80/443.

Render-конфигурация render.yaml сохранена в проекте как запасной вариант, но для этой установки она не используется.


БЕСПЛАТНЫЙ ЗАПУСК С ANDROID-ТЕЛЕФОНА (ДЛЯ ТЕСТА)

Важно: телефон может запустить Node.js-сервер, но это не превращает мобильную сеть в стабильный круглосуточный дата-центр. Android может остановить процесс в фоне, телефон будет нагреваться и разряжаться, а мобильный оператор часто использует CGNAT. Поэтому такой способ подходит для тестов и небольших сессий, но не является надёжным публичным хостингом.

Вариант A — игра по одной Wi-Fi-сети (бесплатно и без внешнего хостинга)

1. На Android установи Termux из официального источника проекта Termux (не старую сборку из Google Play).
2. Открой Termux и выполни:
   pkg update && pkg upgrade -y
   pkg install nodejs-lts unzip -y
3. Помести ZIP проекта в папку Download и дай Termux доступ к файлам:
   termux-setup-storage
4. Перейди в папку загрузок и распакуй архив:
   cd ~/storage/downloads
   unzip Stick-main-2.4-android-host.zip
5. Запусти сервер:
   cd Stick-main
   npm install
   npm start
6. На самом телефоне открой http://127.0.0.1:8080.
7. Чтобы друг подключился по тому же Wi-Fi, узнай локальный IPv4 телефона в настройках Wi-Fi и открой на устройстве друга http://АДРЕС-ТЕЛЕФОНА:8080. Например, http://192.168.1.25:8080.
8. В меню «Онлайн» у обоих должен использоваться один и тот же адрес. В локальной сети это будет IP телефона и порт 8080.

Чтобы Android не усыплял тестовый сервер:
- Не закрывай Termux и не очищай его из списка последних приложений.
- В Termux можно выполнить termux-wake-lock.
- Для Termux отключи оптимизацию батареи в настройках Android.
- Не оставляй телефон под нагрузкой на солнце или под подушкой; лучше подключить зарядку и следить за температурой.

Вариант B — дать доступ другу через интернет

Для доступа из интернета нужен публичный туннель или сервер с публичным IP. Бесплатные quick-tunnel-сервисы могут выдавать временный случайный HTTPS-адрес, который меняется при перезапуске туннеля. Туннель должен поддерживать WebSocket, а телефон и Termux должны оставаться включёнными. Перед выбором сервиса проверь его актуальные бесплатные лимиты и доступность в сети каждого игрока: они могут меняться.

Не публикуй в интернете адрес без ограничений, если не собираешься следить за сервером. Не сообщай никому SSH-пароли, токены и приватные ключи. Для долгосрочного публичного онлайна лучше VPS; «бесплатный, круглосуточный, без сна и без задержки» тариф нельзя гарантировать.

УПРАВЛЕНИЕ ХОСТИНГОМ С ТЕЛЕФОНА

Сам VPS можно администрировать через мобильный браузер в панели провайдера и SSH-клиент. Но наличие бесплатных ресурсов, свободной мощности, регистрации и оплаты зависит от актуальных условий провайдера. Я не могу проверить текущие условия тарифов и доступность провайдеров на ноябрь 2026 года из этой сессии, поэтому не буду обещать, что конкретный бесплатный VPS сейчас выдаётся всем новым аккаунтам.

Если цель — играть с другом через интернет без постоянного выключения сервера, сначала проверь RTT из меню «Онлайн» в разное время суток и с обоих подключений. Место сервера выбирай по фактическому RTT, а не только по стране дата-центра.


ЗАПУСК БЕЗ VPS С ТЕЛЕФОНА
