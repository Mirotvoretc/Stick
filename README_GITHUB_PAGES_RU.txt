STICK ARENA 2.4.1 — ПУБЛИКАЦИЯ НА GITHUB PAGES

ПОЧЕМУ РАНЬШЕ ПОЯВЛЯЛАСЬ «ГОЛАЯ» СТРАНИЦА

GitHub Pages для обычного репозитория публикует проект в подпапке:
https://USERNAME.github.io/REPOSITORY/

В предыдущем index.html CSS и JavaScript подключались от корня домена:
/css/styles.css и /js/core.js

Из-за этого браузер искал файлы по адресам https://USERNAME.github.io/css/... и https://USERNAME.github.io/js/..., минуя папку репозитория. В версии 2.4.1 подключения исправлены на относительные пути ./css/... и ./js/..., которые работают и в подпапке GitHub Pages, и при размещении в корне домена.

КАК ПРАВИЛЬНО ЗАГРУЗИТЬ ПРОЕКТ

1. Скачай архив Stick-Arena-2.4.1-GitHub-Pages.zip и распакуй его.
2. Открой получившуюся папку Stick-main.
3. Зайди в свой репозиторий GitHub в браузере.
4. Нажми Add file → Upload files.
5. Перетащи ИМЕННО СОДЕРЖИМОЕ папки Stick-main, а не саму папку Stick-main целиком.
6. Проверь, что в корне репозитория сразу видны:
   index.html
   папка css
   папка js
   папка tests
   server.js
   package.json
   game-engine.js
   и остальные файлы проекта.
7. Важно: структура не должна получиться такой: Stick-main/Stick-main/index.html. Файл index.html должен лежать в корне репозитория (или в корне выбранной папки публикации).
8. Нажми Commit changes и дождись завершения загрузки.

ВКЛЮЧЕНИЕ GITHUB PAGES

1. В репозитории открой Settings.
2. В боковом меню найди Pages.
3. В блоке Build and deployment выбери Source: Deploy from a branch.
4. В Branch выбери main (или ту ветку, куда загружены файлы).
5. В папке выбери /(root), если index.html находится в корне репозитория.
6. Нажми Save.
7. Подожди, пока GitHub Pages завершит публикацию. Ссылка появится в разделе Pages.
8. Открывай именно опубликованную ссылку, обычно вида https://USERNAME.github.io/REPOSITORY/.

ЕСЛИ ВЫБРАНА ПАПКА /docs

Если в настройках Pages указано /docs, GitHub ищет сайт внутри docs. В таком случае помести содержимое Stick-main внутрь docs, чтобы получилась структура docs/index.html, docs/css/styles.css и docs/js/core.js. Не оставляй index.html рядом с папкой docs, если Pages настроен на /docs.

ЕСЛИ СТРАНИЦА ВСЁ ЕЩЁ БЕЗ ОФОРМЛЕНИЯ

1. Открой опубликованный сайт.
2. В адресной строке вручную проверь адрес таблицы стилей, заменив конец URL на:
   REPOSITORY/css/styles.css
   Например: https://USERNAME.github.io/REPOSITORY/css/styles.css
3. В браузере должна открыться длинная таблица CSS, а не страница 404.
4. Так же проверь JavaScript:
   https://USERNAME.github.io/REPOSITORY/js/core.js
   Должен открыться текст JavaScript.
5. Если вместо файлов 404, проверь расположение index.html, css и js и выбранную папку публикации в Settings → Pages.
6. После нового Commit сделай полную перезагрузку страницы. На компьютере Ctrl+Shift+R. На телефоне закрой вкладку, открой сайт заново; при необходимости очисти кэш сайта.

ЧТО МОЖЕТ И ЧЕГО НЕ МОЖЕТ GITHUB PAGES

GitHub Pages — статический хостинг. Он раздаёт HTML, CSS, JavaScript и другие статические файлы, но не запускает Node.js-процесс server.js и не обслуживает WebSocket-сервер игры.

Поэтому после публикации на GitHub Pages:
- оформление и клиентская часть игры должны загружаться;
- локальные режимы, которые работают в браузере, могут запускаться на странице;
- сетевой матч через комнаты не заработает только от одного GitHub Pages.

Для онлайна отдельно запусти server.js на Node.js-хостинге (например, VPS или другом хостинге с постоянно работающим Node.js и WebSocket). В меню игры открой «Онлайн», вставь публичный HTTPS-адрес игрового сервера и нажми «СОХРАНИТЬ АДРЕС». Для страницы GitHub Pages сервер должен поддерживать защищённый WebSocket WSS. Если сервер и сайт находятся на одном хосте, адрес сервера можно будет подставлять автоматически, но с GitHub Pages обычно требуется указать адрес отдельного сервера.

ФАЙЛЫ СЕРВЕРА

server.js, package.json, Dockerfile и docker-compose.yml хранятся в том же репозитории для удобства исходного кода, но GitHub Pages не выполняет их. Их нужно отдельно развернуть на Node.js-сервере. Не пытайся указать server.js как стартовый файл GitHub Pages — Pages не является Node.js-хостингом.

ПРОВЕРКА

В package.json добавлен тест tests/pages.test.js. Он проверяет, что все CSS/JS ссылки относительные, файлы существуют и пути корректно разрешаются в подпапке репозитория, как на GitHub Pages.
